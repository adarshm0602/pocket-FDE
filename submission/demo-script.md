# Pocket FDE — three-minute demonstration

Use https://pocket-fde-adarsh.vercel.app/. Keep API keys, the signing key, developer settings and private access notes out of the recording. Enter the demo access code before recording starts. Use only the synthetic case library.

## 0:00–0:25 — The problem and workspace

“Pocket FDE helps a support engineer turn an incident into an owner hypothesis and an evidence plan. Knowledge from resolved cases is reviewed and carried forward. This demonstration uses a fictional platform; it is not evidence of real-world accuracy.”

Show the case library and existing incident/analysis layout. State that customer guides, platform definitions, reviewed cards and learning notes are searched together.

## 0:25–1:05 — Keyword search

Select CASE-101, choose Keyword search and inspect sources. Expand CARD-001 and a customer guide. Show the platform version and version caveats. Analyze the incident. Read the returned owner as a hypothesis, show the diagnostic questions and logs, and explain that suggested changes require confirming evidence.

If the provider is overloaded or the owner is wrong, show the error or wrong output honestly. Do not edit a result to match the expected answer.

## 1:05–1:40 — Hybrid search

Keep the same case and switch to Hybrid search. Show that the old analysis clears. Inspect the sources, then analyze again after the cooldown. Explain that this mode combines exact terms and local MiniLM embeddings while sharing the same corpus, model and triage rules.

“Two retrieval methods are available for comparison. This short demo does not establish that hybrid always performs better.”

## 1:40–2:15 — Work survives refresh

Refresh the page and show the restored result and selected mode. Use Saved analyses to reopen the earlier Keyword result. Explain that drafts stay in this browser and completed analyses are saved in private cloud storage for this browser's workspace.

## 2:15–2:40 — Missing evidence and safety

Select CASE-573544. Show that its platform version remains unknown and that analysis requires confirmation. Inspect sources without selecting a version. Show a version caveat and explain that the tool escalates weak or incomplete evidence rather than inventing a verified fix.

## 2:40–3:00 — Review and next evidence

“A completed analysis automatically creates a provisional learning in Second Brain. Open View learning, check its evidence and version scope, and approve or reject it. Only approved learning becomes available to both searches, without redeployment. We have a working hosted mechanism and controlled development evaluations. Matched person-alone, agent-alone and pair trials with a real participant remain necessary to establish collaborative benefit.”
